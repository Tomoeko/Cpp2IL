# Loops and direct managed calls

This preparation fixture has four selected methods: the implicit constructor, `Step`, `Run` and `RunUntil`. `Step` is marked `NoInlining` and changes two instance fields. The loops carry an index and sum across a direct managed call, with an optional early exit after the call's side effects. There are no static field initializers, generic methods, value-type arguments or stack-passed managed parameters in this scope.

The independent driver specifies 983 observations: one fresh instance checking both default field values, 75 direct calls, 450 complete loops, 450 loops with a stop condition and seven null-receiver cases. The fresh-instance check observes constructor behavior before either field is overwritten. Inputs cover negative and zero counts, single and repeated iterations, signed overflow, existing call counts, zero-delta side effects, early exits and the absence of a receiver access when no iteration runs. The Python oracle uses triangular and tetrahedral closed forms with explicit 32-bit wrapping for accumulated values; it does not execute recovered code to compute expected results.

This is a prepared source fixture, not an acceptance result. Before claiming loop coverage, inspect the exact Unity 2021.3.35f1 Windows x64 Release IL2CPP output to confirm that the calls and back edges survive optimization. Subsequent validation must recover the complete four-method assembly from isolated player inputs, verify managed IL, compare declarations, compile the generated source, rebuild the native player and check the independent observations. Do not remove failed methods from the denominator or patch generated source.

The anticipated boundaries are loop-carried phi values, parallel copies on back edges, values live across calls, field side effects, native register widths and explicit null-check/throw paths. Broader argument layouts, indirect calls, arbitrary loops and whole-program equivalence remain outside this finite fixture.
